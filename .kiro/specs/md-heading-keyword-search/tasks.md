# Implementation Plan

- [ ] 1. 基盤: スクリプト雛形とPesterテストフィクスチャの準備
  - `Search-MdHeading.ps1`を新規作成し、`-Path`/`-Keyword`を非Mandatoryのパラメータとして宣言するparamブロックのみを用意する(対話的プロンプトを避けるため)
  - サブフォルダを複数階層持つMarkdownテスト用フィクスチャファイル一式を用意する。`#`/`##`見出し、`###`以降の見出し、見出し以外の本文行、キーワードを含む見出し/含まない見出しをそれぞれ含める
  - `.md`ファイルが1件も存在しないフォルダ用のフィクスチャも用意する
  - Pesterによるテスト実行基盤(テストファイルの配置場所と命名規則)を整備する
  - Observable: `Invoke-Pester`でテストランナーが正常に起動し、用意したフィクスチャファイル一式が期待するディレクトリ構成で存在することを確認できる
  - _Requirements: 5.1, 5.2_

- [ ] 2. パラメータ検証機能の実装(必須指定・空文字列・パス存在確認)とユニットテスト
  - `-Path`/`-Keyword`が指定されているか検証し、未指定または空文字列の場合はファイルアクセスが発生する前に、それぞれ判別可能なエラーメッセージを伴う終了エラーを送出するロジックを実装する
  - `-Path`が既存かつアクセス可能なディレクトリを指しているかを検証し、存在しない場合は専用のエラーメッセージを伴う終了エラーを送出するロジックを実装する
  - Pesterユニットテストで、未指定・空文字列・パス不存在の各ケースがそれぞれ判別可能なメッセージで拒否され、有効な入力(存在するパスと非空キーワード)では検証を通過することを確認する
  - Observable: 上記4パターンすべてに対するPesterテストがパスし、無効な入力では後続の検索処理へ進まないことがテストで裏付けられる
  - _Requirements: 1.1, 1.2, 1.3, 1.4_
  - _Boundary: ParameterValidator_

- [ ] 3. Markdownファイル探索機能の実装(再帰的な.md収集)とユニットテスト
  - 検証済みの`-Path`配下を再帰的に走査し、拡張子が`.md`であるファイルのみを収集する関数を実装する。ディレクトリの深さによらずすべてのサブフォルダを対象に含める
  - 該当ファイルが1件も存在しない場合は空のコレクションを返す(メッセージ表示は行わない)
  - Pesterユニットテストで、ネストしたフィクスチャフォルダから期待どおりの`.md`ファイル一覧が取得できること、および対象ファイルが存在しないフォルダで空の結果が返ることを確認する
  - Observable: フィクスチャフォルダに対する関数呼び出しが、既知の`.md`ファイル一覧(サブフォルダ内のファイルを含む)と一致する結果を返すことがテストで確認できる
  - _Requirements: 2.1, 2.2, 2.3_
  - _Boundary: MdFileDiscovery_

- [ ] 4. 見出し検索・キーワード一致機能の実装(HeadingSearcher)
- [ ] 4.1 見出し行の検出とキーワード部分一致判定の実装
  - 行頭が`#`(レベル1)または`##`(レベル2)で始まる行のみを見出し行として判定し、`###`以降の見出し行と見出し以外の本文行を対象から除外するロジックを実装する
  - 見出し記号と直後の空白を除いた見出しテキスト部分を抽出し、`[regex]::Escape`でエスケープしたキーワードとの部分一致を大文字小文字を区別せずに判定するロジックを実装する
  - 一致した見出し行ごとに、ファイルパス・見出し階層・見出しテキスト・見出し該当行のテキストを持つ結果オブジェクトを生成する
  - Observable: `#`/`##`見出しのみがヒット候補として評価され、`###`見出しと本文行は候補から除外されることがコードとテストの両方から確認できる
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_
  - _Boundary: HeadingSearcher_

- [ ] 4.2 見出し検索のユニットテスト整備
  - `#`/`##`のみがヒットし、`###`および本文行が除外されることを確認するテストを追加する
  - 大文字小文字を区別しない部分一致(例: キーワードと見出しで大文字小文字が異なる組み合わせ)を確認するテストを追加する
  - キーワードに正規表現特殊文字(`.`, `*`, `[`等)が含まれる場合でもリテラル文字列として扱われ、意図しない一致や例外が発生しないことを確認するテストを追加する
  - 見出しテキストにキーワードが含まれない場合、結果コレクションに含まれないことを確認するテストを追加する
  - Observable: 上記すべてのケースを網羅したPesterテストがパスする
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_
  - _Boundary: HeadingSearcher_

- [ ] 5. 検索結果のコンソール表示機能の実装(ResultPresenter)とユニットテスト
  - 集約された検索結果を`FilePath`単位でグループ化し、ファイルごとに見出し階層・見出しテキスト・該当行テキストをコンソールへ表示するロジックを実装する。結果はファイルへは一切出力せず、標準出力のみに書き込む
  - 集約結果が空の場合、ヒットなしを示すメッセージを1件表示するロジックを実装する
  - Pesterユニットテストで、複数ファイルにまたがる結果がファイルごとに判別可能な形式で表示されること、および結果が空の場合にヒットなしメッセージが表示されることを確認する
  - Observable: 複数ファイル分の結果を渡した際、出力中にどのヒットがどのファイルに属するか判別可能な行が含まれることがテストで確認できる
  - _Requirements: 4.1, 4.2, 4.3, 4.4_
  - _Boundary: ResultPresenter_

- [ ] 6. パイプライン統合: スクリプト全体のオーケストレーションと分岐処理の実装
  - パラメータ検証 → ファイル探索 → 見出し検索 → 結果表示、の順に各機能を呼び出すトップレベルのスクリプトフローを実装する
  - パラメータ検証またはパス存在確認が失敗した場合、以降の処理(ファイル探索・検索)を一切実行せずに終了するよう分岐させる
  - ファイル探索結果が0件の場合、見出し検索を行わずに対象ファイルなしメッセージを表示して終了するよう分岐させる
  - 外部モジュールのインポートを行わず、Windows PowerShell 5.1およびPowerShell 7+の組み込み機能のみでスクリプトが完結するようにする
  - Observable: フィクスチャフォルダ(見出しヒットあり/ヒットなし/ファイルなし/パラメータ不正/パス不存在)に対してスクリプト全体を実行すると、それぞれ要件どおりの出力(検索結果一覧、各種エラーメッセージ、対象ファイルなしメッセージ、ヒットなしメッセージ)が得られる
  - _Requirements: 1.2, 1.3, 1.4, 2.3, 5.1, 5.2_

- [ ] 7. エンドツーエンドの統合テストと性能確認
- [ ] 7.1 エンドツーエンドの統合テスト整備
  - サブフォルダを含むフィクスチャツリーに対しスクリプト全体を実行し、期待どおりの集約結果(ファイルパス・見出し階層・見出しテキスト・該当行テキスト)が得られることを確認する統合テストを追加する
  - `.md`ファイルはあるがキーワードにヒットする見出しがないフォルダに対して実行し、ヒットなしメッセージが表示されることを確認する統合テストを追加する
  - `.md`ファイルが存在しないフォルダに対して実行し、対象ファイルなしメッセージが表示されることを確認する統合テストを追加する
  - `-Path`/`-Keyword`の未指定・空文字列・パス不存在の各ケースでスクリプト全体を実行し、要件どおりのエラーメッセージが表示され検索が実行されないことを確認する統合テストを追加する
  - Observable: 上記シナリオすべてを網羅したPester統合テストがパスする
  - _Requirements: 1.2, 1.3, 1.4, 2.3, 4.3_

- [ ]* 7.2 大量ファイルに対する性能確認
  - 大量(例: 1000件以上)の`.md`ファイルを含むフィクスチャツリーを生成し、スクリプト全体の実行時間を計測する
  - 実用的な時間内(数秒程度)に処理が完了することを確認する
  - Observable: 計測結果が許容時間内に収まることが記録される
  - _Requirements: 5.3_
