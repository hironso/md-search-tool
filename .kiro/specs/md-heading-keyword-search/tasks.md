# Implementation Plan

> **クラウド実行環境における注記**: この開発環境はネットワークポリシー上、PowerShell Gallery等からPesterモジュールをインストールできないため、Pesterによる自動テストの作成・実行はこの環境では行わない。代わりに、各実装タスクでは「動作確認用のサンプルMarkdownフィクスチャファイル」と「実行例・期待される出力」を`README.md`に記録し、`pwsh`での手動実行によって動作を確認する。Pesterによる自動テストスイートの整備・実行は、ユーザーのローカルPowerShell環境で後日行うことを前提とし、該当タスクには「(ローカル実行推奨)」と注記する。

- [x] 1. 基盤: スクリプト雛形とサンプルMarkdownフィクスチャ・手動確認手順の準備
  - `Search-MdHeading.ps1`を新規作成し、`-Path`/`-Keyword`を非Mandatoryのパラメータとして宣言するparamブロックのみを用意する(対話的プロンプトを避けるため)
  - サブフォルダを複数階層持つ動作確認用のMarkdownフィクスチャファイル一式を用意する。`#`/`##`見出し、`###`以降の見出し、見出し以外の本文行、キーワードを含む見出し/含まない見出し、先頭インデント付き見出しをそれぞれ含める
  - `.md`ファイルが1件も存在しないフォルダ用のフィクスチャも用意する
  - `README.md`を新規作成し、フィクスチャのディレクトリ構成、実行例(`pwsh ./Search-MdHeading.ps1 -Path <フォルダ> -Keyword <文字列>`)、および期待される出力を記載する手動確認手順の枠組みを整備する
  - 注記: Pesterによる自動テスト基盤の構築・実行はローカル環境推奨(本タスクでは行わない)
  - Observable: 用意したフィクスチャファイル一式が期待するディレクトリ構成で存在し、`README.md`に記載した実行例をそのまま`pwsh`で実行できる状態になっている
  - _Requirements: 5.1, 5.2_

- [x] 2. パラメータ検証機能の実装(必須指定・空文字列・パス存在確認)
  - `-Path`/`-Keyword`が指定されているか検証し、未指定または空文字列の場合はファイルアクセスが発生する前に、それぞれ判別可能なエラーメッセージを伴う終了エラーを送出するロジックを実装する
  - `-Path`が既存かつアクセス可能なディレクトリを指しているかを検証し、存在しない場合は専用のエラーメッセージを伴う終了エラーを送出するロジックを実装する
  - `README.md`に、未指定・空文字列・パス不存在それぞれの実行例と、表示されるエラーメッセージ・検索が実行されないことを手動確認する手順を追記する
  - 注記: Pesterユニットテストの作成・実行はローカル環境推奨(本タスクでは`README.md`への実行例記録による手動確認に留める)
  - Observable: `README.md`記載の4パターン(未指定/空文字列Path/空文字列Keyword/パス不存在)をそれぞれ`pwsh`で手動実行すると、記載どおりの判別可能なエラーメッセージが表示され、後続の検索処理へ進まないことが確認できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4_
  - _Boundary: ParameterValidator_

- [x] 3. Markdownファイル探索機能の実装(再帰的な.md収集)
  - 検証済みの`-Path`配下を再帰的に走査し、拡張子が`.md`であるファイルのみを収集する関数を実装する。ディレクトリの深さによらずすべてのサブフォルダを対象に含める
  - 該当ファイルが1件も存在しない場合は空のコレクションを返す(メッセージ表示は行わない)
  - `README.md`に、ネストしたフィクスチャフォルダに対する実行例と期待される`.md`ファイル一覧、および`.md`ファイルが存在しないフォルダでの実行例を追記する
  - 注記: Pesterユニットテストの作成・実行はローカル環境推奨
  - Observable: `README.md`記載の実行例を手動実行すると、サブフォルダ内のファイルを含む期待どおりの`.md`ファイル一覧(または対象ファイルが存在しない場合の空の結果)が得られることが確認できる
  - _Requirements: 2.1, 2.2, 2.3_
  - _Boundary: MdFileDiscovery_

- [ ] 4. 見出し検索・キーワード一致機能の実装(HeadingSearcher)
- [x] 4.1 見出し行の検出とキーワード部分一致判定の実装
  - `Get-MdFile`から得た`FileInfo`オブジェクトをパイプで`Select-String -Pattern`へ渡し、名前付きキャプチャグループ`^\s{0,3}(?<hashes>#{1,2})(?!#)\s+(?<text>.*KEYWORD.*)$`(`KEYWORD`は`[regex]::Escape($Keyword)`でエスケープ)を用いて見出し行を検出するロジックを実装する(design.md参照)
  - `###`以降の見出し行、4文字以上のインデントを持つ行、見出し以外の本文行を対象から除外する
  - マッチした`MatchInfo`から`HeadingLevel`(`hashes`グループの文字数)・`HeadingText`(`text`グループの値)・`LineText`(`$match.Line`)・`FilePath`を持つ結果オブジェクトを生成する
  - Observable: サンプルフィクスチャに対して手動実行すると、`#`/`##`見出しのみがヒット候補として評価され、`###`見出しや本文行、4文字以上のインデント行は除外されることが確認できる
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_
  - _Boundary: HeadingSearcher_

- [x] 4.2 見出し検索の動作確認記録の整備
  - `README.md`に、大文字小文字を区別しない部分一致の実行例(キーワードと見出しで大文字小文字が異なる組み合わせ)を追記する
  - `README.md`に、キーワードに正規表現特殊文字(`.`, `*`, `[`等)が含まれる場合でもリテラル文字列として扱われ、意図しない一致や例外が発生しない実行例を追記する
  - `README.md`に、キーワードが見出しに含まれない場合に結果へ含まれないことを示す実行例を追記する
  - 注記: Pesterユニットテストの作成・実行はローカル環境推奨(本タスクでは`README.md`への実行例記録による手動確認に留める)
  - Observable: `README.md`に追記した実行例をすべて手動実行し、記載どおりの結果になることが確認できる
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_
  - _Boundary: HeadingSearcher_

- [ ] 5. 検索結果のコンソール表示機能の実装(ResultPresenter)
  - 集約された検索結果を`FilePath`単位でグループ化し、ファイルごとに見出し階層・見出しテキスト・該当行テキストをコンソールへ表示するロジックを実装する。結果はファイルへは一切出力せず、標準出力のみに書き込む
  - 集約結果が空の場合、ヒットなしを示すメッセージを1件表示するロジックを実装する
  - `README.md`に、複数ファイルにまたがる結果表示例(どのヒットがどのファイルに属するか判別できる形式であることが分かる例)と、ヒットなし時のメッセージ表示例を追記する
  - 注記: Pesterユニットテストの作成・実行はローカル環境推奨
  - Observable: `README.md`記載の実行例を手動実行すると、複数ファイル分の結果がファイルごとに判別可能な形式で表示され、ヒットなし時は専用メッセージが表示されることが確認できる
  - _Requirements: 4.1, 4.2, 4.3, 4.4_
  - _Boundary: ResultPresenter_

- [ ] 6. パイプライン統合: スクリプト全体のオーケストレーションと分岐処理の実装
  - パラメータ検証 → ファイル探索 → 見出し検索 → 結果表示、の順に各機能を呼び出すトップレベルのスクリプトフローを実装する
  - パラメータ検証またはパス存在確認が失敗した場合、以降の処理(ファイル探索・検索)を一切実行せずに終了するよう分岐させる
  - ファイル探索結果が0件の場合、見出し検索を行わずに対象ファイルなしメッセージを表示して終了するよう分岐させる
  - 外部モジュールのインポートを行わず、Windows PowerShell 5.1およびPowerShell 7+の組み込み機能のみでスクリプトが完結するようにする
  - Observable: フィクスチャフォルダ(見出しヒットあり/ヒットなし/ファイルなし/パラメータ不正/パス不存在)に対してスクリプト全体を手動実行すると、それぞれ要件どおりの出力(検索結果一覧、各種エラーメッセージ、対象ファイルなしメッセージ、ヒットなしメッセージ)が得られる
  - _Requirements: 1.2, 1.3, 1.4, 2.3, 5.1, 5.2_

- [ ] 7. 動作確認記録の総仕上げと性能確認
- [ ] 7.1 エンドツーエンドの手動確認記録整備(ローカル実行推奨のPester統合テストの代替)
  - `README.md`に、サブフォルダを含むフィクスチャツリーに対する全体実行例と期待される集約結果(ファイルパス・見出し階層・見出しテキスト・該当行テキスト)を追記する
  - `README.md`に、`.md`ファイルはあるがヒットなしのケース、`.md`ファイルが存在しないケース、パラメータ不正・パス不存在の各ケースについて、実行例と期待されるメッセージを追記する
  - 注記: 上記シナリオをカバーするPesterによる自動統合テストの作成・実行はローカル環境推奨。本タスクでは`README.md`への実行例記録による手動確認に留める
  - Observable: `README.md`に記載したシナリオすべてを手動実行し、要件どおりの出力になることが確認できる
  - _Requirements: 1.2, 1.3, 1.4, 2.3, 4.3_

- [ ]* 7.2 大量ファイルに対する性能確認
  - 大量(例: 1000件以上)の`.md`ファイルを含むフィクスチャツリーを生成し、`Measure-Command`を用いてスクリプト全体の実行時間を計測する(Pester不要、`pwsh`標準機能のみで実施)
  - 実用的な時間内(数秒程度)に処理が完了することを確認する
  - Observable: `Measure-Command`の計測結果が許容時間内に収まることが記録され、`README.md`または本タスクのメモに記録として残る
  - _Requirements: 5.3_
